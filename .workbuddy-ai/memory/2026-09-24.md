## MOBA Demo 阶段一：移动组件与实体根对象

- 新增 `Assets/Scripts/Components/MovementComponent.cs`（`MOBA.Components`）：
  - `[RequireComponent(typeof(NavMeshAgent))]`，Awake 缓存 agent；`SetMoveSpeed / MoveTo / Stop / HasReachedDestination` 四个公开接口。
  - 内部用 `hasDestination` 标记区分「从未下令」与「已到达」；`HasReachedDestination` 同时校验 pathPending、remainingDistance、velocity 归零，避免状态机提前切换。
  - `MoveTo` 前置 `agent.isOnNavMesh` 检查并复位 `isStopped`；`SetDestination` 返回 false 时告警而非静默失败。
  - 只读查询属性：`Speed / HasPath / RemainingDistance / CurrentVelocity`（供表现层与 Debug 视图使用，不暴露 NavMeshAgent 本体）。
- 新增 `Assets/Scripts/Core/EntityBase.cs`（`MOBA.Core`）：持有 `team / entityType / statsData` 三个 SerializeField，公开只读属性 `Team / EntityType / StatsData / Movement`；Awake 取 MovementComponent，Start 调 `ApplyStats()` 注入 MoveSpeed，另有 OnValidate 提示缺失引用。
- 关键设计决策（后续阶段需沿用）：
  - **速度写入路径单一**：EntityBase 不直接改 `NavMeshAgent.speed`，而是调 `MovementComponent.SetMoveSpeed()`（对用户原始需求的唯一偏离，为满足计划书「避免互相修改私有字段」）。
  - **配置注入放在 Start 而非 Awake**：同一 GameObject 上多组件 Awake 顺序不确定，Start 能保证 MovementComponent.Awake 已完成 agent 缓存。
  - 属性名 `EntityType` 与枚举类型同名（color-color），类内如需引用枚举请用全限定名 `MOBA.Core.EntityType.X`。
  - 建筑类实体无 MovementComponent，`EntityBase.Movement` 可能为 null，使用方必须判空。
- 待办提醒：`MoveTo` 目前不做坐标投射，阶段一收尾时应在 `PlayerCommandController` 用 `NavMesh.SamplePosition` 处理点击 NavMesh 外区域（验收标准之一）。

## MOBA Demo 阶段一：玩家输入控制

- 新增 `Assets/Scripts/Controllers/PlayerCommandController.cs`（`MOBA.Controllers`）：
  - Awake 缓存 `Camera.main`、用 `LayerMask.NameToLayer` 解析 "Ground" 层并转位掩码；任一依赖缺失则 LogError + `enabled = false`（把配置错误挡在初始化阶段，避免每帧刷日志）。
  - Update 监听 `Input.GetMouseButtonDown(1)` → `ScreenPointToRay` → 单次 `Physics.Raycast`（限定地面掩码 + `QueryTriggerInteraction.Ignore`）。
  - 落点用 `NavMesh.SamplePosition` 吸附（`snapToNavMesh` 可关），吸附失败则告警并忽略指令 —— 这条直接满足验收标准「点击 NavMesh 外区域不报错、不失控」。
  - 空引用三层保护：相机缺失 / 受控实体未赋值（Awake 警告一次，Update 静默 return）/ `Movement` 为 null（建筑实体，用 `hasWarnedMissingMovement` 只告警一次）；另提供 `SetControlledEntity()` 支持运行时赋值。
  - 未引入 `EventSystem.IsPointerOverGameObject` 判断（避免阶段一强依赖 UGUI），等 HUD 落地后需补「点击 UI 不触发移动」。

## MOBA Demo 阶段一：静态审查 + Debug 注入

对三个脚本做了全量覆盖式修改（非增量）：

- **日志分级策略定稿**（后续沿用）：
  - 致命依赖缺失 → `Debug.LogError`：NavMeshAgent 缺失、Camera.main 缺失、Ground Layer 不存在、EntityStatsData 未配置、英雄/小兵缺 MovementComponent。
  - 合法但可疑 → `Debug.LogWarning`：塔/基地误挂 MovementComponent、MoveTo 时不在 NavMesh、点击点附近无可通行区域。
  - 全部用「一次性标记」（`hasReportedMissingAgent` / `hasWarnedMissingMovement`）防止 Update 路径刷屏；配置类错误集中在 Awake 报出后 `enabled = false`。
- **Gizmos**：`MovementComponent.OnDrawGizmosSelected` 画路径折线（青）、目的地（绿球）、steeringTarget（黄球）、stoppingDistance（橙球）；`PlayerCommandController.OnDrawGizmos` 画原始点击点（黄）、实际落点（绿）、吸附偏差线（品红）、单位到目标连线（青）。运行时数据不持久化，退出播放模式即消失。
- **移动指令日志**：成功下达时输出受控单位名、目标点坐标、点击点坐标、吸附距离，用 `{v.ToString("F2")}` 而非插值格式符（避免 Vector3 格式化坑）。
- **RequireComponent 的边界（重要决策）**：只在 `MovementComponent` 上声明 `[RequireComponent(typeof(NavMeshAgent))]`。`EntityBase` **不能**声明 RequireComponent(MovementComponent)（塔/基地按设计没有移动组件，强声明会让 Unity 自动补 NavMeshAgent）；`PlayerCommandController` 也不声明 RequireComponent(EntityBase)（它挂在场景管理器上、通过 Inspector 引用英雄，便于对局开始时赋值/后续切换英雄）。改用运行期按 EntityType 校验依赖。
- 环境限制：本机无 Unity 安装、无 .NET SDK（仅 runtime），**无法做真实编译校验**，本次为人工静态审查 + 括号/编码结构检查。用户首次进 Unity 编译时若报错需回报。
