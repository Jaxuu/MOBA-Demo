## 1. 项目定位与最终愿景

本项目基于 Unity 3D（团结引擎 Tuanjie 2022.3.61t14），最终交付物不是一个"底层测试框架"，而是一个：

> **带有美术表现、核心机制完整、真正可玩的「简易版英雄联盟」（MOBA Vertical Slice）**。

三条验收主线：

| 主线 | 内容 |
|---|---|
| **核心机制完整** | 英雄右键移动/普攻 + 完整技能系统（指向性 / 非指向性 / Buff-Debuff）+ 防御塔仇恨 + 出兵推塔摧毁基地的完整对局闭环 |
| **美术表现** | 真实 3D 角色与建筑模型、Animator 状态机动画、攻击特效（VFX）与音效（Audio）、MOBA 贴图场景，彻底告别白盒胶囊体 |
| **玩家心流体验** | 世界空间血条、伤害飘字、小地图、击杀播报与计分板、死亡复活倒计时——让玩家"看得懂战局、感受得到反馈" |

**当前进度**：阶段一 ~ 阶段五**已完成**（数据驱动属性、组件装配、NavMesh 寻路、FSM 小兵 AI、塔/基地/兵线/胜负闭环，以及英雄右键指令层、顶视角相机与一键自动化战场组装，纯白盒形态）；**阶段六待开发**。

**版本定位**：单机离线运行，**不涉及**网络同步、预测回滚与服务器权威。

## 2. 总体需求定义

### 2.1 核心玩法 (Gameplay)

#### 2.1.1 英雄控制

英雄是**全项目唯一接收玩家输入的实体**。

| 能力 | 需求描述 |
|---|---|
| **移动** | 鼠标右键点击地面 → `NavMeshAgent` 寻路移动；点击不可达点 / NavMesh 外不得报错 |
| **普攻** | 鼠标右键点击敌方单位 → 追击至射程后按攻击间隔自动平A |
| **指令判定** | 单次右键通过 `Physics.Raycast` 同时获取"敌方单位命中"与"地面命中"，比较命中距离决定**攻击 or 移动**；点自己与友方一律忽略 |
| **相机** | 主相机平滑跟随英雄（固定世界偏移 + 阻尼），支持平移与缩放，不跟随旋转 |
| **死亡** | 死亡后原地静止 → 进入复活倒计时 → 在出生点重生（见 §2.1.5） |

> 架构约束：英雄**刻意不挂载 `EntityAIController`**。FSM 会自主索敌并写 `Movement`/`Combat`，与玩家指令争夺同一对组件，因此英雄行为完全由玩家指令层（`PlayerCommandController`）驱动。

#### 2.1.2 技能系统

技能由 **`ScriptableObject`（`SkillData`）完全数据驱动**，策划改资产即可调整技能，无需改代码。

| 技能形态 | 需求描述 |
|---|---|
| **指向性技能** | 锁定一个敌方目标 → 发射**弹道（Projectile）**，弹道有真实飞行时间，**命中时**结算伤害与效果 |
| **非指向性 AOE 技能** | 指定方向/落点 → 在半径范围内收集所有敌方单位并结算伤害（可含延迟生效的表现前摇） |
| **辅助 / 控制技能** | 对指定友方施加护盾，或对指定敌方施加控制（定身 / 减速 / 眩晕） |
| **Buff / Debuff** | 基础状态效果：**减速、眩晕**等；支持持续时间、到期自动解除、重复施加的刷新策略 |
| **CD 与蓝耗管理** | 冷却时间、法力消耗、施法距离校验；CD 中 / 蓝量不足 / 超距 / 目标非法时**拒绝释放且无任何副作用** |

**首批技能规划**：`Q` = 非指向性 AOE 伤害；`W` = 指向性控制或护盾；后续可扩展指向性弹道技能。

#### 2.1.3 防御塔机制

- 不可移动实体，固定位置索敌，具有较大的攻击范围与较高的单次伤害。
- **仇恨优先级（Aggro Priority）**：

| 优先级 | 规则 |
|---|---|
| 1 | **默认优先级：小兵 > 英雄**（同优先级内取最近者） |
| 2 | **英雄抗塔转移仇恨**：敌方英雄在塔的交战半径内**攻击己方英雄**时，塔立刻把仇恨转移到该敌方英雄 |
| 3 | 仇恨对象**死亡 / 离开交战半径 / 变为非法目标** → 按优先级重新选择 |
| 4 | 塔**同一时刻只攻击一个目标**；目标重评估按节流周期（≤0.25s）执行，禁止每帧重算 |

- 塔的攻击索敌半径 = `CombatComponent.AttackRange`（塔不持有独立索敌半径）。

#### 2.1.4 核心循环

```text
开局 → 双方基地按固定波次间隔规律出兵 → 小兵沿兵线推进并自动交战
     → 玩家英雄介入（清兵 / 消耗 / 抗塔）→ 推掉防御塔 → 摧毁敌方基地 → 判定胜负
```

- 兵线：一"方"一条兵线（阵营 + 出生点 + `LanePath` 三者绑定），蓝红用**节点顺序相反**表达推进方向。
- 终结：任一方基地生命值归零，判定胜负、冻结战场、显示对局结果。

#### 2.1.5 对局信息与玩家心流

| 需求 | 说明 |
|---|---|
| **复活机制** | 英雄死亡 → 复活倒计时（UI 显示）→ 在己方出生点重生并恢复满状态 |
| **击杀播报** | 屏幕顶部播报击杀事件（谁击杀了谁），带队列与自动淡出 |
| **计分板** | 双方击杀数/死亡数实时统计与显示 |
| **小地图** | 将世界坐标映射到小地图，显示双方单位/建筑/英雄位置 |

### 2.2 美术与表现 (Art & Presentation)

#### 2.2.1 模型替换（告别白盒）

英雄、小兵、防御塔、基地**全部替换为标准 3D 模型**；白盒（胶囊体/方块）仅作为开发期过渡形态与调试后备，不作为最终交付形态。

#### 2.2.2 Animator 状态机

使用 Unity **Animator**（Animator Controller + 参数）实现状态与平滑切换，**将 FSM 逻辑状态映射到美术动画**：

| 动画状态 | 触发条件 |
|---|---|
| `Idle` 待机 | 无移动输入、无攻击/施法 |
| `Run` 移动 | 移动速度 > 阈值 |
| `Attack` 攻击 | 攻击指令执行中 |
| `Death` 死亡 | 生命归零（只播一次） |

- 移动/待机由**速度参数**（float `Speed`）驱动过渡，不硬切状态，避免移动↔待机抖动。
- `Spell`（施法）动画可作为扩展状态接入，同一套映射机制。

#### 2.2.3 视觉特效与音效

| 项 | 要求 |
|---|---|
| 普攻弹道 | 有真实飞行时间，命中时结算（不允许"先扣血、后飞弹"） |
| 受击特效 | 在命中位置播放，随单位销毁回收 |
| 技能特效 | AOE 范围表现、护盾/控制表现、指向性技能的弹道表现 |
| 音效 (Audio) | 普攻、受击、技能释放、死亡、建筑摧毁等基础音效 |

- 特效与音效**只由表现层播放**，逻辑代码中不得出现具体特效/音频资源引用。

#### 2.2.4 场景美术

地面替换为**真正的 MOBA 贴图场景**（含兵线视觉引导、野区/河道等区域化贴图），告别默认灰白 Plane。

## 3. 架构总览

### 3.1 组件化（ECS 风格）架构

采用 Unity 原生 `MonoBehaviour` 的**组件化架构（ECS 风格）**：实体（Entity）是身份与容器，能力（Component）是单一职责的行为单元，系统（System/Controller）负责编排。

- **不引入**纯 DOTS / ECS 框架（本项目规模下为负收益），但严格保持"实体—组件—系统"的**思维模型**。
- 每个脚本只承担一个明确职责，**禁止"上帝类"**。
- 组件间通过**公开方法 + C# 事件**协作，禁止跨类读写私有字段。

| 层 | 职责 | 典型类型 |
|---|---|---|
| Entity 层 | 身份、阵营、配置、组件引用聚合 | `EntityBase` |
| Component 层 | 单一能力（生命、移动、战斗、目标、技能、动画） | `HealthComponent`、`MovementComponent`… |
| System 层 | 编排与驱动（AI、指令、对局、生成） | `EntityAIController`、`MatchController` |
| Presentation 层 | 只读订阅事件并播放表现 | `WorldHealthBarView`、`Projectile`、`VfxSpawner` |

### 3.2 FSM 有限状态机

- `StateMachine` 为纯 C# 类，状态（`Idle/Move/Chase/Attack/Dead`）由 `EntityAIController` 构造持有，状态之间互不引用。
- 状态只编排组件能力（`MoveTo()` / `TryAttack()`），**不得自行修改生命值或直接操作 `NavMeshAgent`**。
- 状态切换采用**滞回死区**设计，防止在边界距离上反复横跳（见 `MOBA_Demo_Plan.md`）。
- **适用边界**：可移动单位分两条互斥路线——AI 单位走 FSM，玩家英雄走玩家指令层。

### 3.3 数据驱动（ScriptableObject）

- 所有静态数值（生命上限、移速、攻击力、技能参数等）必须通过 `ScriptableObject` 配置。
- 配置资产视为**只读模板**：`currentHealth`、`currentMana`、攻击冷却、当前目标等运行时状态**绝不回写资产**，只存在于组件实例中。

### 3.4 表现与逻辑分离（铁律）

这是本项目的**最高优先级架构原则**，任何代码都必须遵守：

```text
逻辑层（权威）  ──单向广播事件──▶  表现层（只读、可丢失）
CombatComponent / SkillComponent / HealthComponent
        │
        ├─ OnAttackPerformed ─▶ 播放攻击动画 + 特效 + 音效
        ├─ OnDamaged         ─▶ 受击特效 + 伤害飘字 + 血条刷新
        ├─ OnDied            ─▶ 死亡动画 + 播报 + 复活倒计时
        └─ OnSpellCast       ─▶ 施法动画 + 技能特效
```

**硬性约束：**

1. **单向数据流**：逻辑层广播事件，表现层订阅。逻辑层**禁止引用** `Animator`、`ParticleSystem`、`AudioSource`、UI 组件。
2. **严禁反向影响伤害判定**：Animator 的 **Animation Event 只允许触发表现**（特效、音效），**严禁**用它回调伤害结算或修改任何战斗数值。伤害判定**只**由 `CombatComponent`（距离 + CD + 目标合法性）与 `SkillComponent`（CD + 蓝耗 + 施法距离 + 目标合法性）决定。
3. **表现可丢失**：掉帧、动画被裁剪、特效池耗尽都**不得影响对局结果**。逻辑层**不等待动画**——攻击节奏由 `AttackInterval` 决定，与动画片段长度无关（动画只做视觉匹配，必要时调整播放速度适配）。
4. **表现层可整体关闭**：关闭所有动画/特效/音效后，对局逻辑与胜负结果必须完全一致。

### 3.5 技能系统架构（概念说明）

技能系统采用 **「数据 — 效果 — 执行 — 表现」四层分离**：

| 层 | 职责 | 载体 |
|---|---|---|
| **数据层** | 技能的全部可配置参数：标识、图标、冷却、蓝耗、施法距离、目标类型、效果类型、数值、持续时间 | `SkillData`（`ScriptableObject`） |
| **效果层** | 原子化效果与目标选择：伤害、护盾、控制（减速/眩晕）、位移；目标选择器（范围内敌方 / 指定目标 / 指定友方） | `SkillEffect` 枚举 + 目标选择器 |
| **执行层** | **唯一施放入口** `SkillComponent.TryCast(slot, groundPoint, target)`：校验 CD → 蓝量 → 施法距离 → 目标合法性 → 扣蓝 → 起 CD → 执行效果 → 广播 `OnSpellCast` | `SkillComponent` |
| **表现层** | 订阅 `OnSpellCast` 播放施法动画、技能特效与音效 | `VfxSpawner`、`AnimationComponent` |

设计边界（**刻意不做**，避免过度设计）：

- 不建技能行为树、不做连招编辑、不做技能打断/蓄力/多段。
- Buff/Debuff 只做**基础状态效果**（减速、眩晕 + 护盾），不做完整属性修饰器聚合体系。
- 首批技能只支持 Q / W 两个槽位，槽位机制预留扩展。

### 3.6 网络约定

纯单机，**不涉及**帧同步、状态同步、预测回滚与服务器权威。所有随机性不做确定性要求。

## 4. 实体行为规范 (Entity Specifications)

### 4.1 玩家英雄 (Player Hero)

- 唯一的玩家输入接收者（右键移动/攻击 + 技能释放）。
- 行为完全由玩家指令层驱动，**不挂载 `EntityAIController`**。
- 死亡后：停寻路 → 清目标 → 禁用指令层 → 禁用 `NavMeshAgent` 与 `Collider` → 取消可选中 → 进入复活倒计时 → 出生点重生。

### 4.2 双方小兵 (Minions)

- 由 `MinionSpawner` 定时生成，受 FSM 控制。
- **行为优先级**：
  1. **寻路**：沿指定的 `LanePath`（兵线路径点）推进。
  2. **索敌**：在检测半径（Detection Range）内发现有效敌人。
  3. **追击**：脱离兵线追踪敌人，但不得超过最大追击半径与牵引锚点距离。
  4. **攻击**：进入射程后停止移动并攻击。
  5. **丢失/击杀目标**：目标超出追击半径或死亡后重新寻找目标；无目标则返回兵线继续推进。

### 4.3 防御塔 (Towers)

- 不可移动实体，自动攻击进入范围的敌军，遵循 §2.1.3 的仇恨优先级。
- 死亡后停止一切逻辑，不重复触发死亡收尾。

### 4.4 基地 (Base)

- 不可移动、不可攻击实体，仅作为胜负判定的载体，只广播"被摧毁"事件，不自行判定胜负。

## 6. 开发流规范（铁律）

1. **【场景装配全自动化】** 所有场景装配**必须通过 Editor 脚本自动化完成**（`AutoSceneBuilder` 等），**严禁手动拖拽依赖**。
   - 新增任何需要被注入的字段，必须标 `[SerializeField]`，并在工具中通过 `SerializedObject` / `SerializedProperty` 写入。
   - 手工在 Inspector 里拖的引用**不算交付**：必须回写到工具脚本，否则场景重建即丢失。
   - 工具脚本必须幂等：重复执行结果一致，且只清理自己生成的对象（按固定名字），不做全场景组件扫描删除。
2. **【依赖自校验】** 组件在 `Awake()` 校验必需依赖；缺失即 `LogError` 并 `enabled = false`，不允许静默失败。
3. **【逻辑不依赖表现】** 逻辑层禁止引用 Animator / VFX / Audio / UI；表现层只订阅事件（见 §3.4）。
4. **【配置只读】** 运行时不回写 `ScriptableObject`。
5. **【资产命名与查找】** 专用资产必须从通用查找中排除（避免被误当作通用资产）；`t:GameObject` 会命中 `.fbx`，取预制体须限定 `.prefab`。
6. **【提交前静态检查】** 所有 `.cs` 必须为 UTF-8 with BOM；提交前运行项目内置的结构检查脚本，不得带结构性错误入库。
