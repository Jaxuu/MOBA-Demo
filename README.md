# MOBA Demo - 项目需求与说明文档 (README)

## 1. 项目简介
本项目是一个基于 Unity 3D 的单机顶视角 MOBA（多人在线战术竞技）核心玩法 Demo。
项目旨在通过构建最小化可行产品（MVP），验证 MOBA 游戏的核心系统架构，包括：数据驱动的属性配置、实体组件装配、基于 NavMesh 的寻路、有限状态机（FSM）驱动的小兵 AI，以及基础的伤害结算闭环。

**当前版本定位：** 核心玩法跑通，架构验证，单机离线运行。

## 2. 核心玩法需求约束

### 2.1 游戏流程闭环
- **开局**：玩家操控英雄实体，双方基地按固定时间间隔生成小兵。
- **交战**：小兵沿固定兵线推进，遇敌后自动交战；防御塔攻击进入射程的敌方单位。
- **终结**：任一方基地生命值归零，判定胜负，对局结束。

### 2.2 核心机制说明
- **移动控制**：玩家通过鼠标右键点击地面，发出移动指令。
- **攻击逻辑**：全自动平A（普通攻击）。单位进入有效射程后，按攻击间隔（Attack Interval）自动执行伤害结算。当前版本**不包含**主动技能释放、弹道飞行时间计算及 AOE 伤害。
- **目标选择**：单位仅可攻击敌对阵营目标，不可攻击友方、中立或已死亡单位。

## 3. 实体行为规范 (Entity Specifications)

### 3.1 玩家英雄 (Player Hero)
- 唯一的玩家输入接收者。
- 死亡后不触发自动复活逻辑（当前版本Demo直接结束或原地静止）。

### 3.2 双方小兵 (Minions)
- 由 `MinionSpawner` 定时生成，受 FSM（有限状态机）控制。
- **行为优先级**：
  1. 寻路：沿指定的 `LanePath` (兵线路径点) 推进。
  2. 索敌：在检测半径（Detection Range）内发现有效敌人。
  3. 追击：脱离兵线追踪敌人，但不得超过最大追击半径。
  4. 攻击：进入射程后停止移动并攻击。
  5. 丢失/击杀目标：目标超出追击半径或死亡后，重新寻找目标；无目标则返回兵线继续推进。

### 3.3 防御塔 (Towers) & 基地 (Base)
- **防御塔**：不可移动实体，具有较大的攻击范围和较高的单次伤害，自动攻击进入范围的敌军。
- **基地**：不可移动、不可攻击实体，仅作为胜负判定的载体。

## 4. 技术选型与架构规范

本项目开发需严格遵循以下技术约束，任何新加入的代码必须符合此规范：

- **组件化架构 (MonoBehaviour-based)**：放弃纯 ECS，采用 Unity 原生组件模式。每个组件（如 `HealthComponent`, `MovementComponent`）职责必须单一，禁止编写包含所有逻辑的“上帝类”。
- **数据驱动 (Data-Driven)**：所有静态数值（血量上限、移速、攻击力等）必须通过 `ScriptableObject` 配置，实体在运行时仅读取数据，不可修改源资产。
- **逻辑寻路**：统一采用 Unity 内置 `NavMeshAgent` 进行实体移动和障碍物规避。
- **表现解耦**：第一阶段以胶囊体/方块代替模型，逻辑代码（扣血、寻路）不得直接强耦合具体的特效播放或动画事件。
- **网络约定**：当前架构纯单机，**不涉及**帧同步、状态同步或预测回滚设计。

## 5. 项目目录结构概览
```text
Assets/
├── Art/                # 模型、材质、动画、特效
├── Scenes/             # 测试场景与主玩法场景
├── Scripts/            # 核心业务逻辑 (Core, Components, AI, Controllers)
├── ScriptableObjects/  # 数据配置资产存放处
└── Prefabs/            # 实体预制体
```

## 6.后续迭代规划 (Out of Scope for V1.0）

以下功能不在当前版本实现范围内，但底层架构需留出扩展余地：

- 技能系统（指向性/非指向性技能、Buff/Debuff 状态管理）。

- 装备与经济系统（金币掉落、商店购买）。

- 对象池（Object Pooling）性能优化。

- 多人网络同步。
